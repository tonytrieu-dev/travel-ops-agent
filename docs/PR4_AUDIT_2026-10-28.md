## Must fix

1. **One user can contaminate another user's containment window (F7).**
   [security_evidence.py](../backend/app/security_evidence.py:75),
   [compliance.py](../backend/app/compliance.py:69),
   [models.py](../backend/app/models.py:68).
   - **What this is:** Containment counts denials by tenant/device and whether a
     session exists. It does not separate authenticated users sharing that device ID.
   - **Problem:** Two users in one tenant registered as `demo-device` are accepted.
     Four missing-resource denials from user A plus one from user B revoke B's
     session. Reproduced: B read 200 → A gets four 404s → B gets one 404 → B read 401.
     Migrated users receive that same default device ID, so this is not an exotic state.
   - **Fix:** Include exact session identity in the authenticated containment
     bucket. Make the evaluator and incident uniqueness agree with that boundary;
     do not treat a device label as an authenticated machine identity.
     Default synthetic seeded accounts have distinct devices; migrated or deliberately
     shared-device accounts expose this case, including multiple sessions of one actor.
   - **If we skip it:** An innocent user can be logged out for another user's
     behavior. The earlier unauthenticated-attempt fix does not cover this case.

2. **Browsing flight offers can revoke a legitimate traveler (F8).**
   [BookingModule.tsx](../frontend/src/components/BookingModule.tsx:96),
   [App.tsx](../frontend/src/App.tsx:337),
   [connectors.py](../backend/app/routes/connectors.py:46).
   - **What this is:** Every booking-component mount fetches connector settings.
     Changing the selected offer remounts it; even the initial no-offer view fetches.
   - **Problem:** Connector reads require an operator/admin with MFA. Ordinary
     travelers get 403. Five such reads revoke the traveler's session; the next
     trips read returns 401. Reproduced that API sequence; component effects and
     the offer-based key establish how normal browsing generates it.
   - **Fix:** Use the existing public enforcement setting to skip the legacy
     connector read in enforced traveler booking flows. Keep connector configuration
     privileged; do not grant travelers configuration access to silence errors.
   - **If we skip it:** Normal offer comparison can log users out. The shared-hook
     stop-on-403 fix does not protect this separate mount-time request.

## Should fix

3. **Failed logins still name the targeted user as the actor (F9).**
   [security_identity.py](../backend/app/security_identity.py:200).
   - **What this is:** An operator can filter security events by `actor_user_id`.
   - **Problem:** A stranger submits a victim's email with the wrong password and
     device. The denied event stores the victim as `actor_user_id` despite no
     authenticated source. Reproduced through the operator events API. Removing
     registered-device attribution fixed one containment path but left this false
     actor attribution intact.
   - **Fix:** Leave the actor unknown until verified. Preserve the attempted
     target through the event's resource field rather than its actor field.
   - **If we skip it:** Investigation and report evidence can wrongly attribute
     attempted access to the victim.

4. **The connector error is hidden behind permanent loading (F5, carried forward).**
   [ConnectorsPanel.tsx](../frontend/src/components/ConnectorsPanel.tsx:30).
   - **What this is:** The connector screen fetches once and stores a fetch error.
   - **Problem:** A 403 or network failure leaves `connectors` null. The early
     loading return prevents the error message from ever rendering.
   - **Fix:** Render the initial fetch error before the loading branch.
   - **If we skip it:** Users see endless loading with no explanation or recovery
     guidance. Confirmed from the connected state/error rendering, not a browser run.

5. **The validation matrix cites tests absent from this tree (F6, carried forward).**
   [SECURITY_EVALUATION.md](SECURITY_EVALUATION.md:15).
   - **What this is:** The historical matrix presents named tests as supporting
     evidence for login, isolation/containment and booking-provider failure.
   - **Problem:** The full-roundtrip, revoke-only-attacker and provider-failure
     test names in those rows do not exist. Current enrollment/compliance tests
     cover related behavior, but the containment test does not assert that the
     victim still gets 200. The provider-failure spy exists and no test enables it.
   - **Fix:** Link the tests that actually exist and narrow each claim to its
     assertions. Restore one focused provider-failure regression if keeping that
     behavior as a validated guarantee.
   - **If we skip it:** The report can claim evidence nobody can reproduce from
     the cited tests. Existing suite totals do not repair this evidence mismatch.

## Assessment and limits

The prototype has useful explicit boundaries. No new ownership bypass or role/MFA
bypass was established in this audit. That is narrower than a claim that no bypass
exists. Device authentication and network micro-segmentation remain known scope
gaps, not newly discovered implementation bugs.

No finding is raised solely for the documented local-process rate limiter,
full-window monitoring reads, local schedule, owner-role audit failure, shared
synthetic credentials, or the absence of an enterprise IdP. Their limits remain
explicit. No speculative abstraction deletion or dependency savings are claimed.

Verdict: fix F7 and F8 before relying on the live demonstration. Correct evidence
attribution and the validation matrix before using those records in the report.

Not checked: browser/end-to-end behavior, real internal/external network paths,
production or distributed load, live model/airline/search providers, crash-replay
experiments, vulnerability advisories/dependency supply chain, or every unchanged
flight-parser/evaluation/cassette branch. Earlier full-suite results were retained;
the suite was not repeated for documentation-only changes. No commit, push or deploy.
